# Thomas O'Neill

I build software with Claude Code, and the checks that keep its output honest.
Rust, TypeScript, WebGPU. London / remote, available for contracts. → [oneilltom.com](https://oneilltom.com)

## Now

**Upfront** (private, going public shortly): a Rust Wayland shell where Claude Code is the agent.
Web pages, Android apps and a Windows VM are panes on a 3D ground, and you drive them by voice.
The agent works through skills and small tool scripts. Fast calls, like scoring the items of a
list or filling in a form from speech, go to small typed models, so they skip an agent turn.

## Built with Claude Code, graded by a reference

Each of these ports is checked against an outside reference, so a change counts only when the
reference agrees. The Claude co-authored commits and the `CLAUDE.md` files are in the history.

- **[three-rs](https://github.com/oneilltomhq/three-rs)**: three.js core and `WebGPURenderer` ported to Rust on wgpu.
  Each example is diffed against three.js's own reference screenshots, using its unmodified comparator. 100 of 215 gradeable pages pass so far.
- **[d3-three](https://github.com/oneilltomhq/d3-three)**: 18 D3 gallery charts in three.js WebGPU, each rendered headless,
  diffed against a committed frame and checked against its data.
- **[d3-hierarchy](https://github.com/oneilltomhq/d3-hierarchy)**: d3-hierarchy 3.1.2 in Rust, doing its operations in the same order as the JS.

Split out of Upfront, on crates.io:

- **[glasspane](https://github.com/oneilltomhq/glasspane)**: a headless Wayland compositor as a Rust library. It hosts real clients and gives you one `wgpu::Texture` per window.
- **[wgpu-dmabuf](https://github.com/oneilltomhq/wgpu-dmabuf)**: Linux dma-buf interop for wgpu.

## How I work with Claude Code

- Every rule in `CLAUDE.md` comes from a failure I actually saw, not one I guessed at. Skills and hooks hold the rest.
- One worktree and one PR per piece of work. Subagents run in parallel, each on the cheapest model that can do its job.
- Before building, probe agents measure the problem and report numbers. Demos are reviewed against a fixed set of questions.
